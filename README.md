# 《修改软件的艺术》Skill

> 戴维·斯科特·伯恩斯坦 (David Scott Bernstein) 著 | [cangjie-skill](https://github.com/kangarooking/cangjie-skill)(RIA-TV++ v2.5)蒸馏 | 10 张能力卡,单入口路由式

把《修改软件的艺术:构建易维护代码的 9 条最佳实践》提炼为可调用能力:小批次交付、需求表达、TDD 节奏、内聚耦合封装、遗留代码改造、技术债偿还、结对协作等。

## 能力清单

| 能力 | 重要度 | 解决什么问题 |
| --- | --- | --- |
| 在问如何做之前先问做什么、为什么做、给谁做 | critical | 怎么写用户故事/验收标准；需求老变/客户说"不是我要的"怎么办；故事卡/需求文档该写到多细 |
| 小批次构建:拆分故事、限制半成品、控制范围 | high | 故事/任务太大怎么拆；为什么估时总不准/任务总挂着90%；要不要限制WIP/看板怎么用；发布周期多长合适 |
| 持续集成:项目的心跳 | high | 集成太痛/合并冲突地狱怎么办；要不要分支/功能开关怎么用；构建要多快/构建失败怎么处理；done 的定义(完成/完整完成/完美完成) |
| 协作:结对编程与回顾会议 | medium | 怎么推行/试行结对编程；两个人一台电脑不是浪费吗；新人怎么快速上手；回顾会议怎么开才有产出 |
| CLEAN 五特质:评估并改善代码质量 | critical | 这段代码质量怎么样/代码评审看什么；什么是好代码/团队怎么统一质量定义；为什么我的代码难测试难修改 |
| 测试先行:红绿重构循环 | critical | 怎么开始TDD/红绿重构怎么走；为什么测试先行/先写测试还是先写代码；TDD试行失败了(测试越写越沉重)哪里做错了；修bug怎么避免复发 |
| 用测试描述行为:判定测试数量与唯一性 | high | 该写多少单元测试/测试要写到什么程度；测试是不是写多了/重复了；边界值怎么选测试点；修完bug怎么防复发/回归测试怎么加 |
| 最后实现设计:演化式设计与意图导向编程 | high | 要不要预先设计/大设计前置还是演化设计；怎么降低圈复杂度；意图导向编程/单一抽象层次怎么做；工厂模式什么时候用/加新变体怎么不改调用方；过度设计vs欠设计/什么时候抽象 |
| 重构遗留代码:安全下手的程序 | critical | 祖传/遗留代码不敢动, 怎么安全修改；重构还是重写；怎么说服老板给重构时间；技术债怎么还/什么时候还；绞杀者模式/抽象分支怎么用；给老系统加新功能前要做什么准备 |
| 度量软件开发:价值导向的7个策略 | medium | 开发团队效率怎么度量/KPI怎么定；用速度考核团队行不行；怎么论证TDD/重构/结对的收益 |

## 安装

```bash
./install.sh                      # 装到 ~/.zcode/skills/beyond-legacy-code
./install.sh ~/my-skills          # 或指定目录(FORCE=1 覆盖)
```

安装后 agent 在触发场景自动调用;也可直接阅读 `references/capabilities/` 下的能力卡,
每张卡为六段结构:R 原文摘引 / I 方法论骨架 / A1 书中应用 / A2 触发场景 / E 可执行步骤 / B 边界。
